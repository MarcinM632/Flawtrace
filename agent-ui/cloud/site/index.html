Built so a report can be trusted

An AI that sounds sure and is wrong costs a QA team more than it saves. Flawtrace is built around checking, not around fluent text.

Agents that learn your product first

Onboarding reads your sources and writes the product overview, glossary, business rules and key flows. Every fact carries the number of the document it came from. A fact without a real source is dropped.

A second agent checks the first

After each report, an independent verifier checks every reference and every claim against the sources. Quotes that are not in the report are discarded, and long, vague sentences are sent back for a rewrite.

Proof for every call

API runs keep a numbered log of each request and response. A defect in the report must point to a call in the log, and the app audits the report against that log before you see it.

From connected sources to a verified report

Set it up once, then give the agents a task. Each stage is optional, so you can run only the part you need.

  1. Connect

    Add Jira, Confluence, a repository, your API specification and your AI key. Tokens are stored encrypted.

  2. Onboard

    One click builds the product knowledge from your sources. Start with a free scan that makes no AI calls and shows what a full run would cost.

  3. Run

    Pick the stages for a task: review, code analysis, test design, API run, UI run. Skip any you do not need.

  4. Learn

    Confirm what was a real defect and what was a false alarm. Both are saved and the agents read them on the next run.

What the agents do

Specialists with their own instructions, not one assistant doing everything.

Static reviewChecks a task against the existing code and specification for gaps, contradictions and impossible requirements, before anyone builds it.
Code analysisReads the change in the repository, its integrations and what it can break outside the changed files.
Test designTurns the findings into test cases with expected results and the source of each expectation.
API test runsExecutes a test process on your test environment through the endpoints in your specification and reports with call-by-call evidence.
UI runsWalks a page in its own browser, also behind a login, and records each step. Your password is kept out of every report and removed when the run ends.
Security sweepA systematic check of your own test environment against OWASP lists, with proof and a retest before anything is reported.

Your AI key. Your cost. No markup.

Flawtrace never sells you tokens. You paste a key from Anthropic, OpenAI or Google, or the address of any OpenAI-compatible service, and the agents use it directly.

A chat subscription is not an API key. A Claude.ai or ChatGPT subscription does not give you one. You create an API key in the provider's developer console, billed separately by the provider. What a run costs depends on the model and the size of the task.
  • The key is stored encrypted and is never shown again. It is sent only to the provider you chose.
  • Every run has limits on steps, tokens and time, so one mistake cannot empty your budget.
  • Token use is recorded for every run, so you can see what a task really cost.
  • Change the provider or model whenever you like. Your knowledge and history stay.

Your data stays yours

Flawtrace reads your tickets and code, so it is built like something that is trusted with them.

Questions

Does it replace testers?

No. It does the reading, cross-checking and first drafts that eat a tester's day, and shows its evidence so a person can decide quickly. The confirmation of a defect stays with you, and your confirmations make the next run better.

How does it avoid made-up facts?

Three checks. Product knowledge is written only from numbered source documents and a fact without a valid source is dropped. Reports must cite their sources, and a second agent verifies the citations. API defects must point to a recorded call. Where the sources are silent, the agent is told to ask, not to guess.

Which AI models work?

Claude, OpenAI and Gemini models through your own API key, and any service that speaks the OpenAI format. The agents were developed and tuned on Claude, so start there. Results on other models depend on the model.

Can it reach a test environment behind our VPN?

Not in the cloud version. Flawtrace Cloud can only call public addresses. Test environments that are only reachable from inside a company network need a self-hosted installation, which is available on request.

What is not available yet?

Generating and running automated pytest suites, which would mean running code on our servers. Private repositories (the beta clones public https repositories; you can also add documents to the knowledge base directly). Connectors that read GitHub and GitLab issues and merge requests.

Who can see my data?

Your colleagues in the workspace. Our staff do not open workspace content unless you ask us for support, and your content is sent only to the AI provider whose key you entered, as part of a run. See the privacy policy and the list of sub-processors.
