# Knowledge base

New here? Start with [GETTING_STARTED.md](../GETTING_STARTED.md).

Every agent reads this folder before it works on a task. Put here what a new tester on the team would need to know.

| File | Content |
| --- | --- |
| how-we-test.md | How the team tests: environments, test data, conventions and what counts as done. Fill it in. |
| test-process.md | The seven activities of the test process and what each Test Flow phase produces. |
| performance-testing.md | How performance testing is planned, designed, run and reported. |
| test-techniques.md | Short reference of the test design techniques the agents use. |

Rules for the content:

- Write facts and rules, not opinions. An agent treats every sentence here as a requirement.
- Name the source of a rule when it comes from a ticket or a page, so it can be checked.
- Keep one topic per file. Add new files freely; the agents list the folder on every run.
- Product knowledge such as business rules, glossaries and system maps can go in subfolders, for example `product/`.
